📋 1. 项目概述

TraceLens 是一个 AI 驱动的 MF4 信号分析工具。用户通过自然语言描述需求，Agent 自动完成信号提取、边沿检测、统计计算、时间窗口查找和可视化出图。


核心链路：

LLM 解析意图"]
    B --> C["📝 Coder
LLM 生成代码"]
    C --> D["⚡ Executor
沙箱执行"]
    D --> E["📊 图片/结果"]
    D -.->|"失败 < 2次"| C
    B -.->|"需求模糊"| F["❓ 追问用户"]

3.3 工作流 (LangGraph)

stateDiagram-v2
    [*] --> Planner
    Planner --> Coder : 需求清晰
    Planner --> Clarify : 需求模糊
    Clarify --> [*] : 返回追问 -> 等待用户补充
    Coder --> Executor
    Executor --> [*] : 执行成功
    Executor --> Coder : 失败 & retries < 2
    Executor --> [*] : 失败 & retries >= 2
节点文件职责
1 Plannerplanner.py
  • 从 MF4 文件读取信号列表 (channels_db，不触发 VLSD 解析)
  • 正则提取用户 query 中的候选信号名
  • 代码侧信号匹配 (精确 -> 大小写 -> 子串)，仅将匹配结果发给 LLM
  • 发现类查询 ("WBA相关信号有哪些") 直接返回，不走 LLM
  • LLM 输出结构化 JSON: {signals, operation, params}
2 Codercoder.py
  • 接收结构化任务 + 工具函数签名
  • LLM 生成完整 Python 代码
  • 重试时附带错误上下文
3 Executorexecutor.py + sandbox.py
  • 代码写入临时 .py 文件
  • subprocess.run() 子进程隔离执行
  • 30s 超时自动终止
  • 从 stdout 解析 SUCCESS: 标记获取图片路径

🔧 4. 工具层 (Tool Scripts)

list_signals list

读取 MF4 文件，返回所有信号名称列表。

list_signals(file_path: str) -> List[str]

利用 channels_db 避免 VLSD 通道解析开销

extract_signal extract

提取指定信号数据，支持时间范围裁剪。

extract_signal(file_path, signal_name, start_time?, end_time?) -> (timestamps, samples)

extract_around_edges detect

检测边沿跳变 (上升/下降/全部)，提取各边沿前后窗口数据。

extract_around_edges(timestamps, samples, edge_type?, ...) -> List[Dict]

find_time_ranges search

按条件 (above/below/equals/between) 查找满足条件的连续时间窗口。

find_time_ranges(timestamps, samples, condition, threshold?, ...) -> List[(start, end)]

支持 min_duration 过滤 + merge_gap 合并

signal_statistics stats

计算信号统计摘要：均值、标准差、最值、RMS、分位数 (数值) 或值分布 (枚举)。

signal_statistics(timestamps, samples, percentiles?) -> Dict

plot_signals viz

多信号曲线绘制，支持 overlay (叠加) 和 split (分栏) 两种模式。

plot_signals(data_dict, title, output_path, primary_signal?, mode?) -> str

自动处理枚举型信号：转整数编码 + 标注原始标签

🔍 6. Planner 信号匹配机制

信号匹配完全在代码侧完成，不消耗 LLM token，避免大文件 (75 万+ 信号) 超限。


flowchart TD
    Q["用户 Query"] --> EX{"正则提取候选"}
    EX -->|"含点分隔符
(EPS_StgTq.Val)"| P["主正则: 高置信度候选"]
    EX -->|"无点分隔符
(WBA, Status)"| S["次级正则: ASCII 关键词"]
    P --> CHK{"发现类查询?"}
    S --> CHK
    CHK -->|"是
'WBA相关信号有哪些'"| DISC["直接搜索 channels_db
返回匹配列表
(不走 LLM)"]
    CHK -->|"否"| MATCH["三阶段匹配:
1. 精确匹配
2. 大小写不敏感
3. 子串匹配 (仅短关键词)"]
    MATCH --> LIMIT{"匹配结果 > 80?"}
    LIMIT -->|"是"| TRUNC["截断至前 80 + 计数"]
    LIMIT -->|"否"| FULL["全量发送"]
    TRUNC --> LLM["LLM 生成 plan JSON"]
    FULL --> LLM
    DISC --> DONE["返回信号列表 -> 追问用户选择"]
匹配阶段策略示例
精确匹配candidate in signal_names"WBA_Status_AWU_..." 完整命中
大小写不敏感candidate.lower() in lower_map"wba_status_awu" -> 正确信号
子串匹配仅对短关键词 (len < 15 且无点)"WBA" -> 匹配所有含 WBA 的信号

🚀 8. 使用方式

安装

pip install -r requirements.txt

启动 Web 界面

streamlit run web/app.py

交互流程

  1. 侧边栏选择 MF4 文件 -- 自动列出 data/ 目录下的 .mf4 文件
  2. 底部输入框描述需求 -- 自然语言描述分析需求
  3. Agent 自动处理 -- Planner 解析意图 -> Coder 生成代码 -> Executor 执行
  4. 结果展示 -- 成功则内联显示图片，失败则展示错误信息和生成的代码
  5. 需求模糊自动追问 -- 信息不足时 Agent 追问补充

💡 9. 关键设计决策

决策点方案理由
信号匹配代码侧正则预处理，不塞给 LLM大文件 75 万+ 信号名会超出 token 上限
代码生成LLM 生成完整 Python 代码比 Function Calling 更灵活，能处理复杂组合
重试机制最多 2 次，附带错误上下文多数语法/逻辑错误一次即可修正
沙箱隔离subprocess.run()进程级隔离比 exec() 安全，无需 Docker
Prompt 管理YAML 文件统一管理便于版本控制和非开发人员调整
工具描述AST 解析源码获取函数签名避免 import asammdf 等重依赖，自动同步
信号列表获取channels_db.keys()避免 iter_channels() 触发 VLSD 数据块解析
